# 151종 몬스터 스프라이트 생성 기획서

## 1. 목적

데스크몬의 장기 콘텐츠로 사용할 오리지널 몬스터 **도감 번호 151개**를 설계하고, 각 번호에 해당하는 48x48 픽셀 스프라이트를 일관된 규칙으로 생성한다.

여기서 151종은 **진화체를 포함한 개별 도감 엔트리 151개**를 뜻한다.

예시:

| 도감 번호 | 개체 |
|---:|---|
| 001 | 몽글이 |
| 002 | 잎몽이 |
| 003 | 꽃몽이 |

즉, 2단 진화 라인은 도감 번호 3개와 이미지 3장을 사용한다. 1단 진화 라인은 도감 번호 2개, 무진화 라인은 도감 번호 1개를 사용한다.

## 2. 핵심 원칙

1. 모든 몬스터는 오리지널 디자인이어야 한다.
2. 특정 기존 프랜차이즈 캐릭터와 형태, 실루엣, 색 조합, 이름이 직접적으로 닮으면 안 된다.
3. 같은 컨셉을 두 번 쓰지 않는다.
4. 한 진화 라인은 실루엣, 색, 생태 키워드가 이어져야 한다.
5. 진화할수록 디테일은 늘리되 48x48에서 읽히는 선을 넘지 않는다.
6. 종마다 대표 실루엣을 먼저 정하고, 색이나 장식은 그 다음에 정한다.
7. 샤이니는 별도 PNG가 아니라 `PaletteSwap.shader`로 처리할 수 있게 기본색과 샤이니색 쌍만 정한다.

## 3. 이미지 스펙

| 항목 | 규칙 |
|---|---|
| 캔버스 | 48x48 px |
| 배경 | 투명 PNG |
| 작업 원본 | 생성 시 마젠타 `#ff00ff` 크로마키 배경 사용 후 투명화 |
| 스타일 | 초기 휴대용 몬스터 RPG풍 오리지널 픽셀 아트 |
| 시점 | 정면에 가까운 3/4뷰 |
| 팔레트 | 기본 5~7색, 최종형은 최대 8색 |
| 외곽선 | 1px 짙은 외곽선 |
| 필터 | Point |
| Mipmap | Off |
| 압축 | None |
| PPU | 100 |
| 피벗 | 기존 프로젝트 설정 유지. 기본은 center, 필요 시 bottom 검토 |

## 4. 진화 라인 규칙

### 4.1 도감 번호 배분

151개는 라인 수가 아니라 **진화체를 포함한 개별 도감 번호 수**다.

정본 원장은 아래 배분을 따른다.

| 타입 | 진화군 수 | 도감 번호 수 | 이미지 수 | 용도 |
|---|---:|---:|---:|---|
| 무진화 개체 | 29 | 29 | 29 | 희귀종, 마스코트형, 기믹형, 이벤트형 |
| 1단 진화군 | 31 | 62 | 62 | 일반 수집 핵심 |
| 2단 진화군 | 20 | 60 | 60 | 메인 성장 라인, 필드 대표종 |
| 합계 | 80 | 151 | 151 | 기본 도감 세트 |

기본 스프라이트는 도감 번호마다 1장씩 만든다. 대기/걷기/샤이니 같은 추가 이미지는 151장 기준 승인 후 별도 배치로 만든다.

### 4.2 단계별 변화량

| 단계 | 크기 | 형태 변화 | 디테일 |
|---|---|---|---|
| 1폼 | 작고 단순 | 핵심 실루엣 1개 | 눈, 몸통, 대표 장식 1개 |
| 2폼 | 1폼보다 15~25% 커짐 | 팔/다리/잎/뿔 등 보조 파츠 추가 | 무늬 1~2개 |
| 3폼 | 라인의 최종 실루엣 | 대표 파츠가 완성형으로 커짐 | 장식은 늘리되 8색 이하 |

### 4.3 진화 연결 금지 사항

- 1폼과 2폼이 아예 다른 동물처럼 보이면 실패.
- 최종형에서 색상이 완전히 바뀌면 실패.
- 장식이 많아져 얼굴이 안 읽히면 실패.
- 48x48 안에서 머리 장식이 잘려 보이면 실패.
- 진화할수록 오히려 작거나 약해 보이면 실패. 단, 의도된 "압축형/현자형" 라인만 예외.

## 5. 중복 방지 체계

각 몬스터 라인은 아래 6개 축의 조합으로 정의한다. 같은 조합은 다시 쓰지 않는다.

| 축 | 예시 |
|---|---|
| 생물 베이스 | 젤리, 새, 벌레, 돌, 버섯, 종이, 물방울, 기계, 별빛 |
| 소재 | 잎, 이끼, 유리, 잉크, 구름, 자석, 촛불, 실, 수정 |
| 성격 | 수줍음, 장난, 느긋함, 경계심, 호기심, 졸림 |
| 움직임 | 걷기, 깡총, 떠다님, 굴러감, 순간이동, 꿈틀 |
| 서식지 | 초원, 숲, 호수, 사무실, 밤, 이벤트 |
| 실루엣 | 둥근형, 세로형, 납작형, 날개형, 뿔형, 꼬리형 |

컨셉 원장에는 반드시 `unique_key`를 둔다.

예시:

```text
unique_key = jelly + sprout + calm + grass + round
unique_key = paper + crane + weekday_work + office + angular
unique_key = moss + turtle_shell + slow + lake + squat
```

이미 존재하는 `unique_key`와 3개 이상 겹치면 재설계한다.

## 7. 희귀도와 네임밸류

희귀도는 두 축으로 나눈다.

1. `rarity`: 게임 시스템상 출몰 확률과 생산량에 쓰는 값.
2. `prestige_class`: 세계관상 네임밸류. 전설, 환상, 초월급 같은 포지션.

이 둘을 합치면 밸런스가 꼬인다. 예를 들어 "지역 전설처럼 유명하지만 실제 출몰은 Rare"인 종, "시스템상 Legendary지만 스토리상 전설은 아닌 희귀 생물"을 만들 수 있어야 한다.

### 7.1 시스템 희귀도 분포

현재 코드 호환을 위해 `Common`, `Rare`, `Epic`, `Legendary` 4단계를 기본으로 둔다.

| 희귀도 | 도감 엔트리 수 | 역할 |
|---|---:|---|
| Common | 89 | 초반 수집, 필드 기본종, 2단 진화 다수 |
| Rare | 38 | 조건부 출몰, 1단 진화 중심 |
| Epic | 11 | 강한 실루엣, 특수 행동, 늦은 필드 |
| Legendary | 13 | 극저확률, 무진화 또는 특수 엔트리 |
| 합계 | 151 |  |

### 7.2 네임밸류 등급

`prestige_class`는 이미지 생성과 도감 설명의 톤을 정하는 값이다. 출몰 확률과 반드시 일치하지 않는다.

| prestige_class | 도감 엔트리 수 | 의미 | 진화 규칙 |
|---|---:|---|---|
| None | 128 | 일반 생물 | 자유 |
| RegionalIcon | 12 | 특정 필드의 대표 마스코트 또는 상징종 | 1~3단 가능 |
| LocalLegend | 5 | 지역 설화급. 희귀하지만 친근한 전설 | 보통 무진화 또는 1단 |
| Legendary | 4 | 세계관 전설급. 필드의 질서를 상징 | 대부분 무진화 |
| Mythic | 1 | 환상급. 특정 조건/이벤트로만 만남 | 무진화 권장 |
| Transcendent | 1 | 초월급. 도감 최상위 네임밸류 | 무진화 고정 |
| 합계 | 151 |  |  |

용어는 필요하면 한국어 표기로 바꾼다.

| 내부값 | 표시 후보 |
|---|---|
| RegionalIcon | 지역 상징 |
| LocalLegend | 지방 전설 |
| Legendary | 전설 |
| Mythic | 환상 |
| Transcendent | 초월 |

### 7.3 네임드 종 디자인 규칙

전설/환상/초월급은 화려함보다 **한눈에 기억되는 실루엣**이 우선이다.

- 전설급은 필드 하나의 핵심 자연현상이나 개념을 대표한다.
- 환상급은 귀엽거나 이상하지만 포획 조건이 특이해야 한다.
- 초월급은 151종 전체에서 단 1개만 둔다.
- 전설급 이상은 같은 소재를 일반종에 먼저 쓰지 않는다.
- 전설급 이상은 진화 라인으로 남발하지 않는다.
- 초월급은 색상 수를 늘리는 대신 형태를 단순하고 상징적으로 만든다.

예시 포지션:

| 포지션 | 컨셉 예시 |
|---|---|
| Grass 전설 | 계절을 깨우는 씨앗 사슴 |
| Lake 전설 | 호수 수면에 뜨는 달고래 |
| Office 전설 | 모든 마감 시간을 먹는 시계 정령 |
| Dream 환상 | 잠들 때만 보이는 베개 별 |
| Transcendent | 데스크탑 세계의 시간/커서/창을 상징하는 단일 존재 |

## 8. 파일 명명 규칙

### 8.1 후보 생성 파일

생성 후보는 기존 에셋을 덮어쓰지 않는다.

```text
Assets/Sprites/<id>_stage1_ai_v1.png
Assets/Sprites/<id>_stage2_ai_v1.png
Assets/Sprites/<id>_stage3_ai_v1.png
```

예시:

```text
Assets/Sprites/mongle_stage1_ai_v1.png
Assets/Sprites/mongle_stage2_ai_v1.png
Assets/Sprites/mongle_stage3_ai_v1.png
```

현재 실험 파일은 `mongle_ai_v1.png`가 1단계 역할을 한다. 대량 생산 전에는 `mongle_stage1_ai_v1.png`로 맞추는 편이 좋다.

### 8.2 승인 후 정식 파일

승인된 최종 파일은 프로젝트 런타임 규칙에 맞춘다.

```text
Assets/Sprites/<id>_0.png
Assets/Sprites/<id>_1.png
Assets/Sprites/<id>_2.png
```

또는 현재 구조처럼 한 종 대표 이미지 하나만 쓰는 경우:

```text
Assets/Sprites/<id>.png
```

현재 프로젝트의 `SpeciesData.formSprites`는 한 종 안의 단계별 스프라이트를 담을 수 있다. 다만 도감 정책은 진화체마다 개별 번호를 부여하므로, 구현 시에는 각 단계가 별도 도감 엔트리로도 조회되게 연결해야 한다.

## 9. 컨셉 원장 스키마

151개 도감 엔트리 생성 전, 아래 표를 먼저 채운다. 이 표가 없으면 이미지 생성 금지.

| 컬럼 | 설명 | 예시 |
|---|---|---|
| dex_no | 개별 도감 번호 | 001 |
| id | 영문 식별자 | mongle |
| ko_name | 한국어 이름 | 몽글이 |
| en_name | 영어 이름 | Mongle |
| evo_group_id | 같은 진화군 식별자 | mongle |
| evo_stage | 현재 진화 단계 | 1 |
| evo_total | 진화군 전체 단계 수 | 3 |
| previous_dex_no | 이전 진화체 번호 | 없음 |
| next_dex_no | 다음 진화체 번호 | 002 |
| field | 필드 | Grass |
| subfield | 확장 필드 | Meadow |
| rarity | 희귀도 | Common |
| prestige_class | 네임밸류 등급 | None |
| core_concept | 한 줄 컨셉 | 새싹 젤리 |
| dex_summary | 도감 기초 설명 | 햇살을 머금고 말랑하게 자라는 새싹 젤리 |
| unique_key | 중복 방지 키 | jelly+sprout+calm+grass+round |
| silhouette | 대표 실루엣 | 둥근 젤리, 잎 줄기 |
| palette | 기본색 | #8fd977 |
| shiny | 샤이니색 | #f5a3d0 |
| behavior | 행동 패턴 | Calm |
| image_status | todo/draft/review/approved | draft |
| notes | 금지/주의 | 기존 캐릭터 닮지 않게 |

전설급 이상은 아래 컬럼도 채운다.

| 컬럼 | 설명 | 예시 |
|---|---|---|
| legend_role | 세계관에서 상징하는 개념 | 계절의 시작 |
| reveal_condition | 만나는 조건 | 봄 이벤트, 금요일 밤 |
| signature_shape | 48x48에서 반드시 보여야 하는 실루엣 | 씨앗 뿔과 사슴 목 |
| forbidden_overlap | 일반종과 겹치면 안 되는 소재 | 씨앗 사슴, 봄 왕관 |

## 10. 이미지 생성 프롬프트 템플릿

### 10.1 1폼

```text
Use case: stylized-concept

Primary request: Create an original <field/theme> monster named <id>, <core_concept>. It must be a new original design and must not resemble any existing franchise character.

Composition/framing: single full-body creature centered, three-quarter front view, readable silhouette, generous padding.
Scene/backdrop: perfectly flat solid #ff00ff chroma-key background for background removal.
Color palette: <palette>, darker shadow, pale highlight, deep muted outline, white/black eyes only.
Constraints: original design only; one creature only; no text; no watermark; no UI; no cast shadow; no floor; no reflection; do not use #ff00ff in the creature.
```

### 10.4 네임드/전설급 추가 문장

`prestige_class`가 `LocalLegend` 이상이면 기본 프롬프트에 아래 문장을 추가한다.

```text
Prestige: <prestige_class>. This monster should feel memorable and iconic, with one strong symbolic silhouette rather than many small decorations. It represents <legend_role>. Keep it original and avoid resemblance to any existing legendary monster design.
```

`Transcendent`는 아래 문장을 추가한다.

```text
This is the single highest-prestige creature in the 151-line set. Make it simple, symbolic, and instantly recognizable at 48x48. Do not make it busy, armored, or overloaded with effects.
```

### 10.2 2폼

```text
Use case: stylized-concept

Scene/backdrop: perfectly flat solid #ff00ff chroma-key background for background removal.

Constraints: must read as the same evolution line; original design only; one creature only; no text; no watermark; no existing franchise resemblance.
```


## 11. 후처리 규칙

생성 이미지는 보통 1024px 이상의 큰 캔버스로 나온다. 프로젝트에 넣기 전에 반드시 후처리한다.

1. 마젠타 배경을 투명 알파로 제거한다.
2. 몬스터 외곽 바운딩 박스를 잡는다.
3. 정사각 크롭을 만든다.
4. 48x48로 nearest-neighbor 리사이즈한다.
5. 1폼은 40~42px 안에 들어오게 한다.
6. 2폼은 42~44px 안에 들어오게 한다.
7. 3폼은 44~46px 안에 들어오게 한다.
8. 팔레트를 5~8색으로 줄인다.
9. 완전 투명 픽셀과 완전 불투명 픽셀만 남기는 것을 기본으로 한다.
10. Unity `.meta`를 생성하고 Point 필터, mipmap off, alpha transparency를 확인한다.

## 12. 검수 체크리스트

### 12.1 단일 스프라이트 검수

- [ ] 48x48인가
- [ ] 투명 배경인가
- [ ] 1px 외곽선이 있는가
- [ ] 작은 크기에서도 눈과 실루엣이 읽히는가
- [ ] 색상 수가 과도하지 않은가
- [ ] 기존 유명 캐릭터를 떠올리게 하지 않는가
- [ ] 바탕화면 위에 올려도 묻히지 않는가

### 12.2 진화 라인 검수

- [ ] 1폼, 2폼, 3폼의 색 계열이 이어지는가
- [ ] 대표 파츠가 단계별로 성장하는가
- [ ] 최종형이 가장 강한 실루엣을 가지는가
- [ ] 단계별 크기 차이가 보이는가
- [ ] 중간형이 최종형의 축소판처럼만 보이지 않는가
- [ ] 최종형이 과밀하지 않은가

### 12.3 151종 전체 검수

- [ ] `unique_key` 중복이 없는가
- [ ] 같은 필드 안에서 같은 실루엣이 반복되지 않는가
- [ ] 초록/파랑/보라 등 특정 색에 과도하게 몰리지 않는가
- [ ] 둥근 젤리형이 너무 많지 않은가
- [ ] 무진화 희귀종이 충분히 특별해 보이는가
- [ ] Office 필드가 단순 사물 의인화만 반복하지 않는가
- [ ] Legendary가 너무 장식 과잉이 아닌가
- [ ] `prestige_class`가 있는 종이 실제로 일반종과 다른 네임밸류를 갖는가
- [ ] 전설/환상/초월급의 소재가 일반종과 겹치지 않는가
- [ ] 초월급은 151종 중 정확히 1개인가

## 13. 생산 순서

### 13.1 1차 파일럿

먼저 10개 도감 엔트리만 만든다.

| 필드 | 도감 엔트리 수 |
|---|---:|
| Grass | 2 |
| Forest | 2 |
| Lake | 2 |
| Office | 2 |
| Special | 1 |
| Event | 1 |

목표는 스타일 고정이다. 파일럿에서 아래를 결정한다.

- 48x48 안에서 적정 크기
- 최종형 디테일 허용량
- 외곽선 두께와 색
- 팔레트 축소 방식
- 마젠타 제거 임계값

### 13.2 2차 배치

파일럿 승인 후 30개 도감 엔트리를 만든다. 이때부터 컨셉 원장의 중복 방지 규칙을 실제 적용한다.

### 13.3 전체 배치

나머지 111개 도감 엔트리를 20~25개 단위로 나눠 만든다.

각 배치마다 순서는 같다.

1. 컨셉 원장 작성
2. 중복 검사
3. 해당 도감 번호의 스프라이트 생성
4. 같은 진화군의 앞뒤 단계 연결성 검수
5. 후처리
6. 48x48 검수
7. Unity 임포트
8. 도감 번호와 `SpeciesData.formSprites` 또는 별도 진화 관계 데이터 연결

## 18. 승인 기준

한 도감 엔트리는 아래 조건을 만족해야 승인한다.

1. 해당 도감 번호의 48x48 원본 PNG가 존재한다.
2. `.meta`가 존재한다.
3. 컨셉 원장 행이 완성되어 있다.
4. `unique_key` 중복이 없다.
5. 진화체라면 같은 진화군의 앞뒤 단계와 실루엣, 색, 소재 연결성이 유지된다.
6. Unity에서 Sprite로 정상 임포트된다.
7. 실제 오버레이 화면에 배치했을 때 실루엣이 읽힌다.
