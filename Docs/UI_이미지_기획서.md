# UI 이미지 기획서

베이스캠프 카드/패널에 쓸 UI 이미지의 생성 사양. 현재 UI는 단색 사각형
플레이스홀더(코드 드로잉)로 돌아가며, 여기 정의된 이미지가 생성되면
`UIKit`의 팔레트/배경만 교체해 적용한다.

크리처 도트와 같은 파이프라인을 쓴다 - 생성 시 마젠타(`#ff00ff`) 크로마키 배경,
투명화 후 PNG, Point 필터. 참조: `픽셀_스타일_가이드.md`,
`151종_몬스터_스프라이트_생성_기획서.md` §3.

## 1. 공통 스타일

- 컨셉: **초기 휴대용 몬스터 RPG의 메뉴 창** - 두꺼운 밝은 테두리 + 안쪽 어두운 면.
  게임보이 시절 대화창의 문법을 데스크탑 오버레이 톤(반투명 진녹색)으로.
- 팔레트: 크리처와 같은 제한 팔레트 감성. 기본 4~6색.
  - 면: 진녹색 계열 `#12190f` ~ `#1c2a18`
  - 테두리: 밝은 연두 `#8fd977` (몽글이 본체색과 동일 - 시리즈 정체성)
  - 포인트: 금색 `#ffe9a3` (베리/샤이니), 분홍 `#ff9ec6` (하트/친밀)
- 픽셀 밀도: 1px = 1px. 안티에일리어싱 금지, 반투명은 면 채움에만.
- 모서리: 2~3px 계단 라운드 (도트 감성의 둥근 모서리)

## 2. 9-슬라이스 프레임 (크기 가변 - 가장 중요)

카드/패널/버튼은 크기가 달라 9-슬라이스로 만든다. **모서리 12px을 고정**하고
가운데가 늘어나는 구조. Unity 임포트 시 Border를 (12,12,12,12)로 지정한다.

| 파일명 | 크기 | 용도 | 비고 |
|---|---|---|---|
| `ui_frame_card.png` | 48x48 | 카드/패널 배경 | 밝은 테두리 2px + 어두운 면. 면은 알파 93% |
| `ui_frame_button.png` | 24x24 | 버튼 (평상시) | 카드보다 얇은 테두리 1px |
| `ui_frame_button_on.png` | 24x24 | 버튼 (선택/활성) | 테두리와 면에 연두 기운 |
| `ui_frame_cell.png` | 16x16 | 도감 폼 칸 (빈 칸) | 홈 파인 느낌 (안쪽 그림자 1px) |

## 5. 생성 프롬프트 골격

각 이미지 생성 시 공통으로 포함할 조건:

```
초기 휴대용 몬스터 RPG풍 오리지널 픽셀 UI, 1px 픽셀 그리드,
안티에일리어싱 없음, 마젠타(#ff00ff) 단색 배경, [크기]px 캔버스,
팔레트: 진녹 #1c2a18 면 / 연두 #8fd977 테두리 / 금색 #ffe9a3 포인트
```

- 9-슬라이스 프레임은 "모서리 장식은 12px 안에, 변은 단순 반복 가능한 패턴"을 명시
- 아이콘은 "실루엣만으로 의미가 읽혀야 함, 디테일 최소" 명시

## 6. 적용 절차 (생성 후)

1. `Assets/Sprites/UI/` 에 넣는다 (크리처와 폴더 분리)
2. 임포트: Sprite, Point, 무압축, PPU 100 - 크리처와 동일 (자동 강제 예정)
3. 9-슬라이스는 Sprite Editor에서 Border (12,12,12,12) 지정
4. `UIKit`의 `Panel()`/`Button()`이 단색 대신 스프라이트를 쓰도록 교체
   - 교체 지점은 `UIKit.cs`에 모여 있다 - 패널/버튼/아이콘 팩토리만 고치면 전체 적용

## 7. 제외 (만들지 않는다)

- 폰트 이미지 - 텍스트는 OS 폰트(맑은 고딕)를 쓴다. 도트 폰트는 한글 수천 자를
  감당할 수 없다
- 크리처 관련 이미지 - 크리처 도트가 그대로 UI 아이콘을 겸한다 (가방/도감 줄)
- 문양(각인) 이미지 - 문양은 인식기 좌표에서 그리므로 이미지가 아니다
