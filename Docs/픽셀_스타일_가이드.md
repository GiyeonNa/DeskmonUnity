# 데스크몬 픽셀 스타일 가이드

포팅계획 §3.5가 요구한 "스타일 가이드 1장". 도트를 그리기 **전에** 규칙을 고정한다.

왜 먼저 고정하는가: 종별로 픽셀 밀도나 아웃라인 규칙이 어긋나면 한 화면에 같이 있을 때
따로 노는 게 바로 보인다. 6종을 다 그린 뒤에 발견하면 6종을 다시 그려야 한다.

참조: 포팅계획 §3(아트), 상세기획 §2(크리처 시트), 기획서 v4 §4.2(라인업)

---

## 0. 한 줄 요약

**48x48 캔버스 · 포켓몬 1세대풍 정지 스프라이트 1장 · 모션은 코드 · 샤이니는 팔레트 스왑.**

---

## 1. 캔버스 규격

| 항목 | 값 | 이유 |
|---|---|---|
| 크기 | **48x48px** 정사각 | 포팅계획 §3.2는 48~64를 허용. 48로 고정한다 — 바탕화면 위 마스코트는 작게 보이고, 픽셀이 적을수록 종당 제작 시간이 짧다 (아트가 병목이므로 §3.5) |
| PPU | **100** | `CreatureView.PixelsToUnits(px) = px/100`과 반드시 일치. 어긋나면 원본 이동 속도 수치가 전부 틀어진다 |
| 필터 | **Point (no filter)** | 도트가 뭉개지지 않게 |
| 압축 | **없음 (Uncompressed)** | 48px에서 압축은 용량 이득이 없고 색만 깨진다 |
| Mipmap | 끔 | 오버레이는 항상 1:1로 렌더된다 |
| 피벗 | **Bottom (0.5, 0)** | 발밑이 기준이어야 착지 스쿼시와 그림자가 어긋나지 않는다 |

임포트 설정은 `PlaceholderSpriteGen`이 코드로 강제한다. 손으로 바꾸지 말 것.

### 캔버스 배분 (48px 기준)

```
  0 ┌────────────────┐
    │  여백 (파츠용)  │  6px  - 잎·귀·갓·모자가 올라가는 자리
  6 ├────────────────┤
    │                │
    │     몸통       │ 34px  - 실제 실루엣
    │                │
 40 ├────────────────┤
    │  그림자 / 여백  │  8px  - 발밑 그림자 + 홉 여유
 48 └────────────────┘
```

몸통이 캔버스를 꽉 채우면 안 된다. 진화 3단계에서 파츠가 커지는데(참나무지기의 가지 뿔,
광대쫑의 대형 갓) 자리가 없으면 잘린다. **상단 6px은 비워두는 것이 규칙이다.**

---

## 2. 팔레트

### 종당 색 수: 4~6색

포팅계획 §3.2는 "Gen-1은 4~15색"이라고 했지만, 우리는 **4~6색으로 더 조인다.**
48px에 15색을 쓰면 색이 뭉쳐서 도트로 안 보인다. 종당 색 구성은 고정한다:

| 역할 | 만드는 법 | 쓰는 곳 |
|---|---|---|
| 본체 | `data.js`의 종 고유색 그대로 | 몸통 대부분 |
| 음영 | 본체 명도 **-12%** | 몸통 하단 1/3 |
| 아웃라인 | 본체 명도 **-30%** | 실루엣 외곽 1px |
| 하이라이트 | 본체 + 흰색 55% | 좌상단 광택 1~2px |
| 파츠색 1~2 | 종별 지정 (아래 §5) | 잎·귀속·갓 등 |

이 4개는 `PlaceholderSpriteGen.Shade()`가 이미 쓰는 값이다. 도트도 같은 규칙을 쓰면
플레이스홀더에서 실물로 교체할 때 톤이 튀지 않는다.

### 눈은 무채색 고정

- 흰자: `#ffffff`
- 동공: `#2a2a33` (순수 검정 X - 48px에서 너무 강하다)

**중요:** 눈에 채도를 넣지 말 것. `PaletteSwap.shader`가 채도 마스크로 무채색 픽셀을
보호하는데, 눈에 색이 섞이면 샤이니에서 눈까지 물든다.

### 샤이니는 그리지 않는다

27폼 전부에 샤이니를 따로 그리면 아트량이 2배가 된다. 셰이더가 처리하므로
**본체 색조를 하나로 유지**하는 것만 지키면 된다. 몸통에 서로 다른 색조를 섞으면
스왑 마스크가 일부만 잡아서 얼룩진다.

---

## 3. 아웃라인 규칙

### 실루엣 외곽: 1px, 본체 명도 -30%

검정 아웃라인은 쓰지 않는다. Gen-1 감성에서 벗어나고, 48px에서 검정 1px은 너무 무겁다.

### 내부 경계: 아웃라인 없음

파츠와 몸통 사이는 색 차이로만 구분한다. 내부에 선을 넣으면 48px에서 뭉갠다.

### 바탕화면 대비는 셰이더가 담당

포팅계획 §3.5의 "배경 위에서 묻히지 않게" 문제는 도트가 아니라
`PaletteSwap.shader`의 `_OutlineWidth`가 푼다 (반투명 검정 테두리, 기본 1px).

**도트에 직접 두꺼운 테두리를 그리지 말 것.** 셰이더 아웃라인과 겹쳐 이중으로 보인다.

---

## 4. 형태 규칙

### 실루엣 우선

48px에서 디테일은 안 보인다. **실루엣만으로 종이 구분되어야 한다.**
확인법: 스프라이트를 전부 검정으로 칠했을 때 어느 종인지 알 수 있으면 통과.

### 픽셀 밀도

- **1픽셀 = 1픽셀.** 2x2 블록으로 그리는 저해상도 스타일을 섞지 않는다.
- 대각선은 계단으로. 안티에일리어싱 금지 (Point 필터라 어차피 뭉갠다)
- 반투명 픽셀 금지. 알파는 0 또는 255만 (그림자 제외)

### 눈

상세기획 §2.1 기준을 48px로 환산:

- 흰자 **2x3px**, 동공 **1x2px**
- 위치: 중심에서 좌우 각 `r*0.34`, 세로는 중심에서 약간 위
- **부엉만 예외** — 눈 1.7배 (`creature.js:213`). 흰자 4x5, 동공 2x3

깜빡임과 커서 추적은 코드가 한다. 눈은 뜬 상태 한 장만 그린다.

### 그림자

발밑 타원, **알파 15%**. 스프라이트에 그려 넣지 말고 별도 오브젝트로 둔다 —
홉(점프) 시 몸만 올라가고 그림자는 바닥에 남아야 한다.

## 5. 종별 파츠 사양

`creature.js drawParts()`를 48px 도트로 환산한 것. **v4 기준 폼 수를 따른다**
(상세기획 §2.2의 3단 표기는 v4에서 재편되었다 - 정본은 `Assets/Data/Species_*.asset`).

### 초원

**몽글이** (3폼, `#8fd977`)
- 0 잎몽이전: 머리 위 새싹 잎 1장, 줄기 2px, 잎색 `#5cb85c`
- 1 잎몽이: 잎 2장 (좌우 대칭 X - 한쪽이 살짝 크게)
- 2 꽃몽이: 분홍 꽃잎 5장 `#ff9ec6` + 노란 중심 `#ffd35c`

**깡총이** (2폼, `#ffd35c`)
- 0: 긴 귀 2개, 길이 = 몸통 높이의 0.9배, 귀속 없음
- 1 왕깡총: 귀 1.4배 + 귀속 분홍 `#ff9ec6` + 머리 중앙 왕관형 귀 1개
- 이동이 점프다 (`hop:true`). 착지 스쿼시가 크므로 **몸통 하단을 평평하게**

**반디** (1폼, `#7dd6ff`)
- 발광 점 3개, 색 `#eafffb`. 몸통 주위 반경 0.5r에 배치
- 광륜(펄스)은 코드/파티클. 도트에는 점만 그린다
- 무진화라 폼이 하나뿐 - 대신 실루엣을 확실히 다르게 (가장 작고 둥글게)

### 숲

**도토리** (3폼, `#b98d5e`)
- 0: 도토리 깍정이 모자 `#7a5a38`, 몸통 상단 절반을 덮는 반원 + 꼭지 1px
- 1 도톨이: 모자에 초록 싹 `#5cb85c` 1개
- 2 참나무지기: 가지 뿔 좌우 2쌍 - **상단 6px 여백을 다 쓴다**

**버섯쫑** (2폼, `#ff8d7b`)
- 0: 빨간 갓 `#e85f4e`, 폭 = 몸통의 1.1배, 흰 점 2개
- 1 광대쫑: 갓 1.35배 + 흰 점 4개 + 2단 갓
- 갓이 몸통보다 넓다 - 48px 폭을 넘지 않게 주의

**부엉** (2폼, `#a98bff`)
- 0: 큰 눈(1.7배) + 귀깃 2개
- 1 현자부엉: 눈썹 깃 + 안경 무늬
- 눈이 실루엣의 핵심. 다른 종보다 얼굴 비중을 크게

## 6. 진화 단계 표현

폼이 올라갈수록:

1. **몸통 크기**: 14 -> 17 -> 21px 반지름 (상세기획 §2.1). 48px 캔버스 기준 비율 유지
2. **파츠 추가/확대**: 없던 것이 생기거나 커진다
3. **색은 유지**: 진화해도 종 고유색은 그대로. 색이 바뀌면 팔레트 스왑이 폼마다 달라진다

**금지:** 진화 단계마다 색조를 바꾸는 것. 샤이니 스왑이 폼별로 어긋난다.

## 7. 제작 파이프라인

1. Aseprite에서 48x48 신규 파일, 배경 투명
2. 이 문서 §2의 5색 팔레트를 먼저 만든다 (종 고유색에서 파생)
3. 실루엣부터 → 본체 채움 → 음영 → 아웃라인 → 하이라이트 → 파츠 → 눈
4. PNG로 `Assets/Sprites/<id>.png`에 **덮어쓴다** (플레이스홀더와 같은 이름)
5. Unity가 자동 재임포트. 임포트 설정은 코드가 강제하므로 손댈 필요 없다
6. `Deskmon/데이터 임포트` 재실행 불필요 - 같은 경로면 참조가 유지된다

### 파일명 (세이브 키와 동일 - 변경 금지)

`mongle` `kkang` `bandi` `dotori` `mush` `owl`
`lumi` `dewdrop` `mossy` `origami` `dozy` `chrono`

### 진화형 파일명 규칙

| 파일 | 폼 |
|---|---|
| `<id>.png` | 기본형 (스테이지 0) |
| `<id>_stage2.png` | 1차 진화형 |
| `<id>_stage3.png` | 2차 진화형 |

`Deskmon/데이터 임포트`가 이 규칙으로 찾아 `SpeciesData.formSprites`에 연결한다.
폼별 파일이 없으면 기본형을 재사용하므로, 기본형부터 그리고 진화형은 나중에 채워도 된다.
임포트 설정(Point·무압축·PPU 100)은 임포터가 강제하므로 파일만 두면 된다.
버전 관리는 파일명이 아니라 git이 한다 - `_v1` 같은 접미사를 붙이지 않는다.

## 8. 검수 체크리스트

종 하나를 그린 뒤 확인한다.

- [ ] 48x48 안에 들어가고, 상단 6px이 비어 있는가 (파츠 자리)
- [ ] 색이 4~6개인가
- [ ] 아웃라인이 1px이고 검정이 아닌가
- [ ] 눈이 무채색인가 (샤이니에서 물들지 않게)
- [ ] 몸통 색조가 하나인가 (스왑 얼룩 방지)
- [ ] 전부 검정으로 칠해도 종이 구분되는가 (실루엣 테스트)
- [ ] 반투명 픽셀이 없는가
- [ ] 바탕화면(밝은 것/어두운 것) 위에 올려봤는가
- [ ] 샤이니 스왑을 켜봤는가 (`CreatureAppearance.shiny = true`)

## 9. 열린 항목

- **진화 3단계 파츠가 48px에 안 들어가는 경우** — 참나무지기(가지 뿔), 광대쫑(대형 갓)이
  후보다. 실제로 그려보고 넘치면 그 폼만 64px로 올리는 대신, **몸통을 줄여서** 해결한다
  (캔버스 크기가 종마다 다르면 정렬이 깨진다)
- **밤 종의 발광 표현** — 반디·부엉. 도트에 넣을지 파티클로 뺄지는 실물을 보고 정한다
